# סטודיו שירה — דף נחיתה

דף נחיתה סטטי, עברית ו-RTL. בלי תלויות, בלי שלב build.

## הרצה

הקבצים משתמשים ב-ES modules, ולכן פתיחה ישירה של `index.html` (file://) תיחסם
על ידי ה-CORS של הדפדפן. צריך שרת סטטי כלשהו:

```bash
npx serve .
# או
python -m http.server 8000
```

ב-VS Code: תוסף Live Server עושה את אותו הדבר.

## אייקון

`tools/make-icons.mjs` מייצר את שלושת הקבצים — `favicon.svg`,
`apple-touch-icon.png` (180) ו-`icon-512.png`.

הצורה מוגדרת בסקריפט כרשימת מקטעי בזייה, וממנה נגזרים **גם** ה-`d` של
ה-SVG **וגם** המצולע שממנו נצרבים קובצי ה-PNG. מקור אמת אחד — אחרת היו
שתי גרסאות של אותה צורה, והן היו מסתעפות בעדכון הראשון.

ה-PNG נכתב ידנית (zlib + CRC32, בלי תלות חיצונית) מתוך סריקת קווים עם
דגימת-על 4×4. לשנות את הצורה = לערוך את `SEGMENTS` ולהריץ מחדש.

## העלאה לאוויר

```
node tools/build.mjs            # תיקיית dist/, חסומה למנועי חיפוש
node tools/build.mjs --public   # פתוחה לאינדוקס — ליום שעולים לדומיין האמיתי
```

זה לא build אמיתי: אין קימפול, אין חבילות, הקוד לא משתנה. הסקריפט רק מעתיק
את **קבצי האתר בלבד**. כל מה שנמצא בתיקייה שמעלים הופך לכתובת ציבורית, ו-
`ROADMAP.md`, `holidays.ics` ו-`tools/` הם פנימיים.

רשימת הקבצים ב-`FILES` מפורשת ולא "כל מה שנגמר ב-js" — **מודול חדש חייב
להתווסף שם**, אחרת הוא לא יעלה והאתר יישבר באוויר ולא בפיתוח.

`images/` ו-`fonts/` מועתקות אוטומטית אם הן קיימות.

**HTTPS הוא חובה ולא נחמדות:** המצלמה במדידה על היד חסומה מחוץ להקשר
מאובטח. כל אחסון סטטי מודרני נותן HTTPS בחינם.

## עדכון תוכן

הכל ב-`data.js`. אין צורך לגעת ב-`main.js`.

**חריג יחיד:** ה-`<h1>` והפסקה הפותחת קיימים גם כטקסט סטטי ב-`index.html`, כדי
שהדף לא ייראה ריק כשה-JS לא רץ. `fill()` ב-`main.js` מדלג על אלמנט שכבר יש בו
טקסט, ולכן שינוי של `heroTitle` / `heroLede` ב-`data.js` מחייב שינוי מקביל
ב-`index.html` (ולרוב גם ב-`<title>` וב-`meta description`).

**שינוי מחיר** — שורה אחת:

```js
{ name: 'לק ג\'ל', price: 150 },
```

**הוספת שירות** — הוספת אובייקט ל-`items` של הקבוצה הרלוונטית:

```js
{ name: 'לק ג'ל מבנה אנטומי', price: 150 }   // סכום בודד
{ name: 'קישוטים', price: 10, priceMax: 20 }  // טווח → "₪10–20"
{ name: 'עיצוב ידני', price: 10, priceNote: 'לציפורן' }
```

`priceMax` ו-`priceNote` אופציונליים. הסכום נעטף ב-`<bdi dir="ltr">` כדי שטווח
לא יתהפך בהקשר RTL.

**הוספת קטגוריית שירותים חדשה** — אובייקט אחד ל-`site.services.groups`:

```js
{
  id: 'makeup',
  title: 'איפור',
  note: 'ניסיון איפור בתיאום מראש.',   // אופציונלי
  items: [
    { name: 'איפור ערב', price: 350 },
    { name: 'איפור כלה', price: 900 },
  ],
}
```

הרינדור לולאתי ולא מכיר שמות קטגוריות, אז זה כל מה שצריך. ה-grid במחירון
(`repeat(auto-fit,minmax(290px,1fr))`) יסדר את העמודה החדשה לבד.

**גוונים** — `site.shades.items`. אלה גווני הלק של הסטודיו. הם נכנסים לשורת
הקיצור של מעצבת הציפורניים, לפני `site.designer.quickColors`, ואינם משפיעים
על צבעי האתר.

**צבעי האתר** — משתני ה-`:root` בראש `styles.css`. שתי הערות:

- `--accent` (קרמל) הוא לקישוט: קווים, מסגרות, נקודות. `--accent-deep` הוא
  לכל מקום שיש בו טקסט לבן על האקצנט — `--accent` עצמו נותן יחס ניגודיות
  של 3.1 מול לבן, מתחת לסף AA לטקסט רגיל. אל תחליפי ביניהם.
- `--wa` הוא ירוק כהה ולא הירוק של וואטסאפ (`#25D366`), מאותה סיבה: לבן על
  הירוק המקורי נותן 2.1.

**שעות פעילות** — `week` בראש `data.js`, מעל `export const site`. מערך לפי
`Date#getDay`: 0 ראשון עד 6 שבת, `null` לסגור.

```js
const week = [
  { open: 9, close: 19.5 },  // ראשון
  // ...
  { open: 9, close: 13.5 },  // שישי
  null,                      // שבת
];
```

שעה שבורה נכתבת כשבר: `13.5` הוא 13:30.

מקור אמת אחד לשלושה מקומות: שורת השעות בפוטר (`ראשון–חמישי 8:00–18:00`,
מקובצת אוטומטית לפי ימים רצופים בעלי אותן שעות), הימים הפתוחים בלוח התורים,
ורשימת השעות ליום שנבחר. `SLOT_HOURS` קובע את המרווח בין לקוחה ללקוחה.

**השעות מיושרות ללוח הפגישות בגוגל** — ראשון–חמישי 9:00–19:30, שישי עד 13:30,
שבת סגור. גוגל היא מה שהלקוחה באמת מזמינה לפיו, ולכן שינוי שם חייב להגיע
גם לכאן, אחרת הפוטר מבטיח שעות שאי אפשר להזמין בהן.

**גלריה** — `site.gallery.items`. כרגע 12 פוסטים מהאינסטגרם של הסטודיו.
הוספת עבודה = שורה אחת. ראי סעיף "גלריה" למטה.

**ביקורות** — `site.reviews.items`. כרגע מערך ריק, ואז `renderReviews()` מסתיר
את הסקשן כולו. להוספה: `{ quote: '...', author: '...' }`.

**פרטי קשר** — `site.footer`, מערך של עמודות. כל פריט ב-`lines` הוא מחרוזת או
`{ text, href }` לקישור. קישור שמתחיל ב-`http` מקבל אוטומטית
`target="_blank" rel="noopener"`.

**וואטסאפ** — `site.whatsapp.href`. הפורמט הוא `https://wa.me/` + מספר בינלאומי
בלי `+` ובלי מקפים: `0548304348` → `972548304348`.

## טאבים

התוכן מחולק לארבעה טאבים המוגדרים ב-`site.tabs`. הכותרת, הכפתור "קבעי תור",
ה-`<h1>`, סקשן קביעת התור והפוטר נשארים קבועים מחוץ להם.

ה-`id` של כל טאב הוא גם ה-`id` של הפאנל (`panel-<id>`) וגם ה-hash בכתובת,
כך שאפשר לשלוח לינק ישר לטאב. הוספת טאב = אובייקט ב-`site.tabs` + `<section>`
מקביל ב-`index.html` עם `id="panel-<id>"`, `role="tabpanel"` ו-`hidden`.

hash שאינו טאב (כמו `#booking`) מושאר לדפדפן, שיגלול אליו כרגיל. המעבר בין
טאבים משתמש ב-`history.replaceState` ולא ב-`location.hash`, כדי לא לגלול
ולא להציף את ההיסטוריה.

כל התוכן נמצא ב-DOM תמיד — הטאבים רק מסתירים אותו ב-`hidden`. זה שומר על
הנראות לזחלני חיפוש.

## גלריה

`gallery.js`, מוטמע ב-`<ul class="grid" data-bind="gallery">`.

שלושה מצבים, והבחירה ביניהם נעשית **לפי התוכן ב-`data.js` בלבד** — אין דגל
מצב ואין קוד להחליף:

| `site.gallery.items` | מה קורה |
|---|---|
| `widget` מוגדר | ווידג'ט חיצוני (גובר על הכל) |
| ריק | ריבועי ממלא מקום מ-`placeholders` |
| `{ image, alt }` | רשת תמונות + לייטבוקס |
| `{ post: 'https://...' }` | הטמעת הפוסט מאינסטגרם |

אפשר לערבב תמונות ופוסטים באותו מערך.

### מסלול א׳ — תמונות מקומיות

הכי טוב מבחינת עיצוב, מהירות ושליטה. שמים קבצים ב-`images/` ומוסיפים:

```js
items: [
  { image: 'images/01.jpg', alt: 'בנייה בג\'ל בנוד עם קישוט על הקמיצה' },
  { image: 'images/02.jpg', alt: 'לק ג\'ל אדום, צורת אלמונד' },
],
```

**`alt` הוא חובה.** זה מה שקורא מסך מקריא, וזו גם דרישת נגישות. לתאר מה
רואים בתמונה — לא "תמונה 1".

התמונות נטענות ב-`loading="lazy"`, ולחיצה פותחת לייטבוקס.

### מסלול ב׳ — פוסטים מאינסטגרם, בלי הרשמה  ← **המסלול הפעיל**

זה מה שכפתור **Embed** של אינסטגרם עצמה נותן: `<blockquote>` והסקריפט
`instagram.com/embed.js`. **אין צורך בחשבון Business, בהרשמה לשירות או
בטוקן.** בפוסט: ⋯ → Embed → Copy Embed Code. מתוך מה שמועתק צריך רק את
הכתובת:

```js
items: [
  { post: 'https://www.instagram.com/p/XXXXXXXXXXX/' },
],
```

הסקריפט נטען רק אם יש פוסטים, ופעם אחת בלבד. אם הוא נחסם או לא נטען, נשאר
קישור עובד לפוסט במקום קופסה ריקה.

הכיתוב של הפוסט מוסתר בכוונה (אין `data-instgrm-captioned`) — זו גלריה,
לא פיד.

**ריל מול פוסט תמונה.** אינסטגרם קובעת את גובה ה-`iframe` לפי יחס המדיה,
אז ריל אנכי יוצא גבוה בהרבה ושובר את יישור הרשת. בתוך `iframe` חוצה-מקור
אי אפשר לעצב, אז `equalizeReels()` משווה מבחוץ: תא הריל מקבל את הגובה
החציוני של פוסטי התמונה, והעודף נחתך ב-`overflow`. הווידאו נשאר שלם —
מה שנחתך הוא שובל הלייקים. המדידה חוזרת בכל שינוי רוחב דרך `ResizeObserver`,
ובלעדיו הרשת פשוט לא מיושרת במקום לקרוס.

אינסטגרם כופה `min-width: 326px` בסגנון inline על ה-`iframe` שהיא מזריקה.
`styles.css` מנטרל את זה ב-`!important`, אחרת הדף גולש לרוחב במובייל.

מגבלות: העיצוב הוא של אינסטגרם (iframe), הפוסט חייב להיות ציבורי, וכל פוסט
מתווסף ידנית. זה **לא** מתעדכן לבד.

### מסלול ג׳ — ווידג'ט חיצוני שמתעדכן לבד

זה המסלול היחיד שמתעדכן אוטומטית בכל פוסט חדש. הוא דורש חשבון
Business/Creator והרשמה לספק (LightWidget או מקביל).

**כרגע כבוי, והסיבה חשובה:** החבילה החינמית של LightWidget מגישה את
הווידג'ט ב-http בלבד, ודפדפן חוסם `iframe` על http בתוך דף https
(mixed content). כלומר החינמי לא יכול לעבוד על אתר אמיתי — רק בלוקאלהוסט.
השדרוג הוא **15 דולר חד-פעמי לווידג'ט**, והוא גם מקצר את זמן העדכון
(בחינמי עד 24 שעות). התצורה של הווידג'ט הקיים שמורה כהערה ב-`data.js`,
כך שהפעלה מחדש היא החלפת `null` בבלוק.

**בצד שלנו זה שדה אחד ב-`data.js`** — אין מה להדביק ב-`index.html`:

```js
widget: {
  src: 'https://cdn.lightwidget.com/widgets/XXXXXXXXXXXX.html',
  script: 'https://cdn.lightwidget.com/widgets/lightwidget.js',
  title: 'עבודות אחרונות מהאינסטגרם',
},
```

`mountGallery()` מחליפה את ה-`<ul>` ב-`<div>` עם `iframe`, וטוענת את הסקריפט
של הספק פעם אחת. ה-`iframe` נבנה בקוד ולא מודבק כ-HTML, כדי שלא יידרש
`innerHTML` בשום מקום בפרויקט.

`widget` גובר על `items` ועל `placeholders`. להסרה: `widget: null`.

**מה שלא בשליטתנו:** מה שקורה בתוך ה-`iframe` הוא של הספק — העיצוב, ה-`alt`
לתמונות, הניווט במקלדת, ו-`prefers-reduced-motion` אם יש שם קרוסלה. יש
`#panel-gallery iframe{max-width:100%}` שמונע גלישה מהרוחב, וזה הגבול.
כדאי לבדוק נגישות אחרי ההטמעה.

### לייטבוקס

`<dialog>` עם `showModal()` — מלכודת פוקוס וסגירה ב-Esc מגיעות מהדפדפן ולא
מקוד. חצים מנווטים (**ב-RTL החץ השמאלי מקדם**), לחיצה על הרקע סוגרת, ויש
מונה "3 מתוך 8". כל התוויות ב-`site.gallery.lightbox`.

## מדידה על היד האמיתית

`tryon.js`, מוצג בתוך המעצבת כתצוגה שנייה — מתג "יד מצוירת / היד שלי" מעל
היד. אותו עיצוב בדיוק, רק על הציפורניים האמיתיות של הלקוחה, בזמן אמת.

### איך זה עובד

MediaPipe Hand Landmarker רץ **בתוך הדפדפן** ב-WASM ומחזיר 21 נקודות ציון
לכל יד. לכל אצבע לוקחים שתי נקודות — המפרק העליון וקצה האצבע — ומהן נגזרים
המיקום, הזווית והגודל של הציפורן.

**התמונה לא עוזבת את המכשיר.** אין שרת, אין העלאה, אין מפתח API. זו לא רק
החלטת פרטיות — זו הסיבה שזה אפשרי בכלל באתר סטטי.

### אותה גיאומטריה כמו היד המצוירת

הציפורן מצוירת מאותם נתיבי SVG שב-`data.js`, באותה תיבה (100×176, עורף
ב-y=170), ובאותה שרשרת טרנספורם כמו `nailTransform()` ב-`designer.js`:
הזזה לעורף, סיבוב לכיוון האצבע, מתיחה, ואז הבאת מרכז העורף לראשית.

**הוספת צורה ב-`data.js` מופיעה בשתי התצוגות.** גם רוחב הציפורניים היחסי
מגיע מאותו שדה `nail` שמצייר את היד המצוירת.

הגימורים מצוירים ב-Canvas במקביל ל-`finishLayers()`. פרנץ' משתמש באותו נתיב
`smile` של הצורה. גימור שאין לו מקבילה נופל לצבע מלא — מוטב פחות מדויק
מאשר ריק.

### הכוונון

`site.designer.tryOn.tuning` — זה מה שמשנים אם הציפורניים יושבות גבוה, נמוך,
צר או רחב. אין כאן ערך נכון אחד, כי זה תלוי במצלמה ובמרחק:

| | מה זה עושה |
|---|---|
| `cuticle` | כמה אחרי המפרק יושב העורף, ביחס למקטע האצבע |
| `width` | רוחב הציפורן ביחס לרוחב כף היד |
| `length` | אורך הציפורן ביחס למקטע האצבע |
| `smoothing` | 1 = מיידי ורועד, 0.2 = חלק אבל עצל |
| `opacity` | מעט שקיפות, כדי שהציפורן האמיתית תציץ מתחת |

הרוחב נגזר מכף היד ולא מהמקטע, כי מקטע מתקצר בפרספקטיבה כשמטים את היד
וכף היד פחות. האורך דווקא נגזר מהמקטע, כדי שאצבע ארוכה תקבל ציפורן ארוכה.

`nailMetrics()` מיוצא בכוונה — זו החתיכה שאפשר לטעות בה בלי לראות, ולכן
היא נבדקת ישירות בלי מצלמה.

### מה נטען, ומתי

המודל הוא כמה מגה-בייט, ולכן נטען **רק בלחיצה על "היד שלי"** ופעם אחת
לכל הביקור. הגרסה מוצמדת ולא `latest` — עדכון אוטומטי של מודל ראייה
ממוחשבת הוא בדיוק סוג הדבר שנשבר בלי שאף אחד נגע בקוד.

המצלמה נכבית ברגע שעוברים חזרה ליד המצוירת, כולל עצירה מפורשת של מסלולי
הזרם — אחרת נורית המצלמה נשארת דולקת.

### מגבלות

- **דורש https.** `getUserMedia` חסום מחוץ להקשר מאובטח. `localhost` נחשב
  מאובטח, ולכן זה עובד בפיתוח; באתר החי זה ידרוש HTTPS (שכל אחסון סטטי
  נותן בחינם).
- תאורה חלשה וציפורניים קצרות מאוד יורידו דיוק.
- קישוטים מוצבים וציור ידני אינם מצוירים בתצוגה החיה, רק הצבע והגימור.

## לוח התורים

`calendar.js`, מוטמע ב-`<div class="book" data-bind="booking">`.

### המסלול הפעיל: לוח הפגישות של גוגל

`site.booking.embed` מכיל את כתובת לוח הפגישות. **כשיש שם `src` הוא גובר על
הלוח המובנה**, בדיוק כמו `widget` בגלריה — אותה תבנית, בחירה לפי נתונים.

```js
embed: {
  src: 'https://calendar.google.com/calendar/appointments/schedules/AcZssZ...',
  href: 'https://calendar.app.google/Ly3JknDB8JBAy7se6',
  title: 'קביעת תור בסטודיו שירה',
  fallback: 'הלוח לא נטען? לקביעת תור בדף של גוגל',
  height: 660,
},
```

`src` הוא הכתובת המלאה שאליה הקישור הקצר מפנה; הקוד מוסיף `?gv=true`, שהוא
מה שמחליף את הדף המלא בתצוגת הטמעה. `href` הוא הקישור הקצר, ומוצג כקישור
גיבוי מתחת ל-`iframe` — חוסם פרסומות או מסגור חסום ישאירו `iframe` ריק, וזה
ההבדל בין "הדף מקולקל" לבין "קבעתי תור".

**למה זה גובר על הלוח שבנינו:** רק גוגל קוראת את היומן האמיתי, ולכן רק היא
יודעת מה תפוס. אירוע פרטי ביומן "שירה" — אימון, פגישה — מעלים את השעה
מהלקוחות מעצמו.

**מה שגוגל לא יודעת, ולכן נשאר באחריותנו:**

- **חגים.** ראי `holidays.ics` למטה. בלעדיו אפשר לקבוע תור ביום כיפור.
- **משך לפי שירות.** בחשבון חינמי יש משך אחד (90 דקות). בנייה לוקחת שעתיים,
  ולכן אחרי הזמנת בנייה צריך להאריך את האירוע ביומן ידנית — וההארכה חוסמת
  את המשבצת הבאה מעצמה, כי בדיקת ההתנגשויות דלוקה.
- **שעות הפוטר.** `week` ב-`data.js` מיושר ידנית ללוח בגוגל. אין סנכרון
  אוטומטי בין השניים.

**למחוק את `embed` → הלוח המובנה חוזר** על כל הלוגיקה שלו. הוא נשאר מתוחזק
ובדוק בדיוק בשביל זה.

### הלוח המובנה — מסלול נסיגה

### מה הוא עושה, ומה הוא בכוונה לא עושה

הלוח יודע מתי הסטודיו **סגור** — שבת, חג, יום שנסגר ידנית, תאריך שעבר, תאריך
מעבר לאופק. הוא **לא** יודע אילו תורים כבר תפוסים, כי אין שרת.

לכן אין בו הודעת אישור. הבחירה נארזת להודעת וואטסאפ מוכנה, והתור נסגר שם.
זה מכוון: לקוחה שלוחצת "אישור" וחושבת שיש לה תור, ומגיעה לסטודיו סגור, היא
נזק אמיתי. `pendingNote` בטקסטים אומר את זה במפורש.

### חגים בלי טבלת תאריכים

`Intl.DateTimeFormat('en-u-ca-hebrew')` מובנה בכל דפדפן ומחזיר את התאריך
העברי של כל תאריך לועזי. לכן טבלת החגים ב-`data.js` נכתבת בקואורדינטות
עבריות ונכונה לכל שנה קדימה, בלי עדכון שנתי:

```js
{ month: 'Tishri',            day: 10, name: 'יום כיפור' },
{ month: ['Adar', 'Adar II'], day: 14, name: 'פורים' },
```

שמות החודשים באנגלית כי הם המפתח, ושמות אנגליים יציבים יותר בין גרסאות ICU.
מערך = כמה שמות אפשריים: בשנה מעוברת אדר מתפצל ל-`Adar I` ול-`Adar II`,
ופורים נופל תמיד באחרון שבהם. בשנה פשוטה השם הוא `Adar` בלי מספר.

**להסרת חג — למחוק שורה. להוספה — להוסיף שורה.** אין לוגיקה להתאים.
חול המועד סוכות ופסח נשארו פתוחים בכוונה.

קצה יחיד שהטבלה לא תופסת: כשתשעה באב חל בשבת הצום נדחה לעשירי באב. באותה
שנה להוסיף את התאריך ל-`closedDates`.

### שירות, משך, ומשבצות

`minutes` על פריט במחירון הופך אותו לשירות שאפשר לקבוע עליו תור. פריט בלי
`minutes` הוא תוספת — מופיע במחירון, לא ברשימת השירותים.

```js
{ name: 'לק ג\'ל מבנה אנטומי', price: 150, minutes: 60 },
{ name: 'בנייה בג\'ל',          price: 220, minutes: 120 },
{ name: 'מניקור בלבד',          price: 80,  minutes: 30 },
{ name: 'השלמת ציפורן',         price: 15 },   // תוספת
```

הרשימה נבנית מ-`serviceGroups` בשלמותה, ולכן קטגוריה חדשה (איפור) נכנסת גם
למחירון וגם לקביעת התור בלי לגעת בקוד.

`SLOT_STEP` (90 דקות) הוא **המרווח בין תור לתור** — רשת שעות ההתחלה.
`minutes` של השירות קובע אם המשבצת **נכנסת עד הסגירה**. שני אלה ביחד:

| שירות | יום רגיל (9:00–19:30) | שישי (9:00–13:30) |
|---|---|---|
| מניקור, 30 דק׳ | 9:00 … 18:00 (7 משבצות) | 9:00 … 12:00 (3) |
| לק ג'ל, שעה | 9:00 … 18:00 (7) | 9:00 … 12:00 (3) |
| בנייה, שעתיים | 9:00 … 16:30 (6) | 9:00 … 10:30 (2) |

בנייה ב-18:00 לא מוצעת כי היא תיגמר ב-20:00. זה לא חוק שנכתב — זה נופל
מהחישוב.

### ימים ושעות

`week` בראש `data.js` הוא מערך לפי `Date#getDay` — 0 ראשון עד 6 שבת, `null`
לסגור. הוא מזין שלושה מקומות בבת אחת: שורת השעות בפוטר, הימים הפתוחים בלוח,
ורשימת השעות ליום שנבחר.

```js
{ open: 9, close: 13.5 },  // שישי
null,                      // שבת
```

`closedDates` הוא מערך תאריכי `YYYY-MM-DD` לסגירות חד-פעמיות — חופשה, יום
אישי, חג שהטבלה לא מכסה.

`leadDays` הוא כמה ימים קדימה מותר להתחיל לבקש (1 = לא להיום), ו-`horizonDays`
עד כמה קדימה הלוח נפתח.

### נגישות

- הרשת היא `role="grid"` עם `role="row"`/`gridcell`, ו-**roving tabindex**:
  תא אחד בלבד נגיש ב-Tab, והחצים מזיזים את הפוקוס. **ב-RTL החץ השמאלי מקדם.**
  `Home`/`End` לקצות השבוע, `PageUp`/`PageDown` להחלפת חודש. חצייה של גבול
  חודש מחליפה חודש במקום להיתקע.
- יום סגור נשאר כפתור עם `aria-disabled` ולא `disabled`: קורא מסך מגיע אליו
  ושומע **למה** הוא סגור — ה-`aria-label` הוא `"21.9.2026 — יום כיפור"`.
- שורת הסיכום היא `aria-live="polite"`.

### שמירה ליומן

הבחירה מיוצרת כקובץ `.ics` (RFC 5545, שורות ב-CRLF) דרך `Blob` ו-
`URL.createObjectURL`. האירוע מסומן `STATUS:TENTATIVE` ולא `CONFIRMED` —
התור לא אושר, והקובץ לא אמור להיראות ביומן כאילו כן.

### חסימת חגים ביומן גוגל

`holidays.ics` בשורש הפרויקט הוא חסימות "עסוק" לכל החגים שבטבלה, לשלוש שנים
קדימה, בשעות העבודה של אותו יום. מיובא ליומן **הראשי** בגוגל.

למה צריך אותו: בלוח הפגישות של גוגל, בחשבון חינמי, הזמינות נבדקת מול היומן
הראשי בלבד. יומן חגים מסוג "יומנים אחרים" לא חוסם כלום, ולכן בלי הקובץ הזה
אפשר לקבוע תור ביום כיפור.

```
node tools/make-holidays.mjs        # 3 שנים
node tools/make-holidays.mjs 5      # 5 שנים
```

הסקריפט קורא את `site.booking.holidays` ואת `week` — אותה טבלה שהאתר משתמש
בה, כדי שלא ייווצרו שני מקורות אמת. **אחרי שינוי בטבלה או בשעות: להריץ
מחדש, למחוק את החסימות הישנות מהיומן, ולייבא את החדש.**

פרטים טכניים: השעות "צפות" (בלי `Z` ובלי `TZID`), ולכן נקראות בשעון המקומי
של היומן ונכונות גם בשעון קיץ וגם בחורף, בלי `VTIMEZONE`. `TRANSP:OPAQUE`
הוא מה שהופך אותן ל"עסוק" ולא ל"פנוי" — בלעדיו הן יוצגו ביומן ולא יחסמו.
שבתות מדולגות כי הן סגורות ממילא.

### להחלפה במערכת חיצונית

למחוק את הקריאה ל-`mountBooking()` ב-`mount()` ולהדביק את ה-embed לתוך
`<div class="book" data-bind="booking">`. שום חלק אחר בדף לא תלוי במודול.

## נגישות ו-RTL

- `dir="rtl"` + `lang="he"`. העיצוב משתמש ב-logical properties
  (`border-inline-start`, `inset-inline-start`) ולא ב-`left`/`right`.
- `@media (prefers-reduced-motion:reduce)` מבטל את כל ה-transitions ואת
  ה-smooth scroll.
- הטאבים מממשים את תבנית ה-tablist של WAI-ARIA: `role="tab"`/`tabpanel`,
  `aria-selected`, ו-roving tabindex. חצים מחליפים טאב, `Home`/`End` קופצים
  לקצוות. **ב-RTL החץ השמאלי מקדם**, כי "הבא" נמצא משמאל.
- כפתורי הבחירה הם `<button>` אמיתיים עם `aria-pressed` ו-`aria-label`.
- הציפורניים ב-SVG הן `role="button"` עם `tabindex="0"` ומאזין `keydown`,
  כי `<g>` אינו כפתור ולא מופעל ברווח או ב-Enter מעצמו.
- שם הגוון והודעת אישור התור הם `aria-live="polite"`.
- `:focus-visible` גלוי בכל הדף, בצבע ה-accent.
- ה-`<h1>` והפסקה הפותחת מגיעים ב-HTML עצמו, כך שגם ללא JS יש לדף כותרת
  ותיאור אמיתיים.

## לא מוגדר עדיין

- **ניסוח** — `heroTitle`, `heroLede`, `gallery.sub`, `gallery.note` הם נוסח
  ממלא מקום שנכתב לדמו, ולא נבדק מול העסק.
- **שעות** — מיושרות ידנית ללוח הפגישות בגוגל. אין סנכרון אוטומטי בין
  השניים; שינוי בגוגל דורש שינוי ב-`week` ובהרצה מחדש של `make-holidays`.
- **משך תוספות** — ל-`השלמת ציפורן` ול-`קישוטים` אין `minutes`, ולכן הן
  תוספות ולא שירותים שנקבעים לבד. להפוך אחת מהן לשירות: להוסיף לה `minutes`.
- **גלריה** — מחוברת לפוסטים מאינסטגרם (מסלול ב׳). **אינה מתעדכנת לבד**:
  כל פוסט חדש הוא שורה ב-`data.js`. נגישות התוכן בתוך ה-iframe היא של
  אינסטגרם ולא שלנו — זו נקודת הנגישות היחידה בדף שאינה בשליטתנו.
- **ביקורות** — `site.reviews.items` ריק בכוונה. כשיתווספו פריטים הסקשן חוזר לבד.
- **פרסי הגלגל** — `site.wheel.prizes` הם הצעה, לא החלטה. הם התחייבות עסקית.
- באנר "דף לדוגמה" בראש הדף (`site.demoFlag`) נשאר עד שכל הסעיפים האלה
  ייסגרו. להסרה: למחוק את `demoFlag` מ-`data.js` — `fill()` יסיר את האלמנט.
